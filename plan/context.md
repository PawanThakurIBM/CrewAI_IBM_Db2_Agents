# Context

## Project Overview

This project is a production-grade demonstration of multi-agent orchestration using CrewAI, Haystack, and IBM Db2. The objective is to showcase how multiple AI agents collaborate, share context, execute tasks in parallel and sequentially, and collectively solve a complex enterprise problem.

The use case chosen for this demonstration is an Airline Delay Management Assistant.

The project is intended as a technical showcase for IBM Bob and demonstrates enterprise-grade orchestration rather than a simple chatbot or RAG application.

---

# Primary Objective

The primary goal is to demonstrate true multi-agent orchestration.

Instead of having a single LLM answer a user's question, the request is broken into multiple specialized tasks that are executed by independent agents coordinated through CrewAI.

Each agent contributes a specific piece of information.

Agents communicate with one another.

Agents reuse previous agent outputs.

Agents share context.

Agents make decisions collaboratively.

Finally, one validated response is returned to the user.

---

# Example User Request

```
Flight AI302 from Delhi to London is delayed because of heavy rain.

What should we do?
```

The system should not answer this directly.

Instead, CrewAI should orchestrate multiple agents that work together before producing a final recommendation.

---

# Multi-Agent Architecture

The project contains specialized agents including:

- Operations Manager Agent
- Weather Agent
- Flight Agent
- Passenger Agent
- Runway Agent
- Aircraft Agent
- Rebooking Agent
- Compensation Agent
- Decision Agent
- Review Agent

Each agent has a well-defined responsibility.

The Operations Manager is responsible for orchestration and task planning.

The Decision Agent combines outputs from all previous agents.

The Review Agent validates the final recommendation before returning it to the user.

---

# CrewAI Orchestration

CrewAI is responsible for:

- Planning execution
- Assigning tasks
- Managing dependencies
- Sharing context
- Executing independent tasks in parallel
- Waiting for dependent tasks
- Passing outputs between agents
- Producing one final response

The project should clearly demonstrate that agents are connected and collaborate instead of operating independently.

---

# Context Sharing

This project should heavily demonstrate context passing.

For example,

Operations Manager

↓

Weather Agent

↓

Weather Result

↓

Decision Agent

The Decision Agent should consume the Weather Agent's output instead of asking the same question again.

Similarly,

Passenger Agent

↓

Rebooking Agent

↓

Decision Agent

The Rebooking Agent should use passenger information generated by the Passenger Agent.

Every downstream agent should build upon previous work.

---

# Shared Enterprise Knowledge

Agents should not hallucinate enterprise policies.

Whenever enterprise knowledge is required, agents should query the IBM Db2 Search Tool.

Examples include

- Airline SOPs
- Compensation rules
- Passenger handling policies
- Airport procedures
- Operational manuals
- Emergency procedures
- FAQs

---

# Haystack + IBM Db2

Haystack is responsible for the enterprise knowledge pipeline.

The ingestion pipeline should:

- Load enterprise documents
- Clean documents
- Split documents
- Generate embeddings
- Store documents inside IBM Db2 Document Store
- Store embeddings inside IBM Db2 Vector Store

During runtime,

CrewAI Agents

↓

IBM Db2 Search Tool

↓

Haystack Retriever

↓

IBM Db2 Vector Store

↓

IBM Db2 Document Store

↓

Retrieved Enterprise Knowledge

The retrieved information is then provided back to the requesting agent.

---

# IBM Db2 Search Tool

The IBM Db2 Search Tool should be implemented as a reusable CrewAI Tool.

Every agent should have access to it.

Internally it should perform semantic retrieval using Haystack.

Agents should never directly query Haystack.

Instead,

Agent

↓

IBM Db2 Search Tool

↓

Haystack

↓

IBM Db2

This keeps the architecture modular.

# Project Architecture

The system consists of four major layers.

1. User Layer

IBM Bob or FastAPI frontend where users submit requests.

2. Orchestration Layer

CrewAI manages the complete workflow.

3. Knowledge Layer

Haystack retrieves enterprise knowledge from IBM Db2.

4. External Data Layer

Public APIs provide real-time operational information.
